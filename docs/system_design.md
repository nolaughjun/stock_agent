**版本**: v1.0  
**日期**: 2026-05-08

## 1. 系统概述

报告智能体系统是一个基于 LangGraph 框架的自动化报告生成平台，采用状态机模式管理报告生成流程，支持 Human-in-the-loop 人工审核机制。

### 1.1 设计目标

- **自动化**: 自动完成规划、收集、撰写、审核全流程
- **可控性**: 支持人工干预和断点恢复
- **可扩展**: 模块化设计，易于扩展新功能
- **可观测**: 完整的日志和链路追踪

## 3. 技术选型

### 3.1 核心技术栈

| 组件 | 技术选型 | 选型理由 |
|-----|---------|---------|
| 状态框架 | LangGraph | 原生支持状态机、checkpoint、interrupt |
| LLM | DeepSeek | 性价比高，中文能力强，支持 JSON 模式 |
| 搜索 | Tavily | 专业搜索 API，返回结构化结果 |
| 可观测性 | LangSmith | LangChain 生态，原生集成 |
| PDF 生成 | pypandoc | 支持复杂排版，中文支持好 |
| 编程语言 | Python 3.14 | 生态丰富，AI 领域首选 |

## 5. 状态设计

### 5.1 状态结构

```python
class ReportState(TypedDict):
    # 1. 任务输入
    topic: str                    # 报告主题
    abstract: str                 # 报告概要
    report_type: Literal[...]     # 报告类型
    language: str                 # 语言
    create_at: str                # 创建时间
    quality_threshold: float      # 质量阈值（可配置）
    
    # 2. 流程控制
    current_step: Literal[...]    # 当前阶段
    retry_count: int              # 重试次数
    max_retry: int                # 最大重试次数
    error_msg: str | None         # 错误信息
    
    # 3. 规划产物
    outline: list[str]            # 报告大纲
    search_queries: list[str]     # 检索词
    
    # 4. 数据收集
    research_sources: Annotated[list[ResearchSource], append_item]
    
    # 5. 对话历史
    messages: Annotated[list, add_messages]
    
    # 6. 报告版本
    draft_versions: Annotated[list[ReportDraft], add_messages]
    
    # 7. 质量控制
    quality_checks: Annotated[list[QualityCheckResult], append_item]
    revision_instructions: list[str]
    human_decision: Literal["approve", "revise"] | None
    human_comments: str | None
    
    # 8. 最终输出
    final_report: str | None
    export_path: str | None
```

### 5.2 状态流转

```
init
  │
  ▼
planning ──────────────────────────────────┐
  │                                        │
  ▼                                        │
researching ◀──────────────────────────┐   │
  │                                    │   │
  ▼                                    │   │
drafting                               │   │
  │                                    │   │
  ▼                                    │   │
reviewing ─────────────────────────────┼───┘
  │               │                    │
  │ (quality<threshold)                │
  ▼               │                    │
revising ─────────┘                    │
  │                                    │
  │ (retry >= max)                     │
  ▼                                    │
finished                               │
  │                                    │
  ▼                                    │
END ◀──────────────────────────────────┘
  │
  │ (error)
  ▼
failed → END
```

## 7. 安全设计

### 7.1 安全措施

| 威胁 | 防护措施 |
|-----|---------|
| API Key 泄露 | 环境变量存储，不硬编码 |
| 路径穿越 | 输出路径限制在安全目录 |
| 输入注入 | 输入长度限制，特殊字符过滤 |
| 资源耗尽 | 请求超时，重试上限 |
| 敏感信息泄露 | 日志脱敏 |

### 7.2 权限控制

- 文件写入限制在 `outputs/` 目录
- API 调用需要有效 Key
- 任务隔离，防止跨任务访问

## 10. 性能设计

### 10.1 性能指标

| 指标 | 目标值 | 测量方法 |
|-----|-------|---------|
| 报告生成时间 | < 10min | 端到端计时 |
| LLM 调用延迟 | < 30s | API 响应时间 |
| 搜索延迟 | < 5s | API 响应时间 |
| 内存占用 | < 1GB | 进程内存监控 |

### 10.2 优化策略

- 使用 LLM 缓存减少重复调用
- 并行执行多个搜索请求
- 流式输出提升用户体验
- 增量保存 checkpoint 防止数据丢失
